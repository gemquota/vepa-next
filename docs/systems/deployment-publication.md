# Deployment publication

## What `dist/` is

`dist/` is the production artifact generated by Vite. It contains the browser application, hashed JavaScript/CSS bundles, the physics worker, static headers, and any explicitly published static resources. It is not the source tree and should never be edited by hand.

The source of truth is:

```text
docs/systems/
```

## Why the atlas is copied into `dist/`

Vite builds `index.html` and imported assets, but it does not automatically publish arbitrary repository folders such as `docs/`. Before this publication step, `/docs/systems/README.md` was handled by the host's single-page fallback and returned the application shell rather than the Markdown document.

The build now runs:

```text
vite build && node scripts/publish-system-atlas.mjs
```

The publisher copies `docs/systems/` to `dist/docs/systems/`. This keeps the documentation authored and reviewed in its normal repository location while making the exact atlas available from the deployed static site.

## Artifact directories

| Directory | Meaning | Delivery policy |
|---|---|---|
| `docs/systems/` | Reviewed source documentation | Canonical and versioned. |
| `dist/` | Vite production output | Generated; publish when the hosting workflow requires checked-in artifacts. |
| `isolate/` | Freebuff hosting mirror/output | Generated hosting artifact; preserve when the workspace tracks it. |
| `public/src/` | Freebuff host adapter artifact | Generated compatibility output; do not hand-edit. |

The application runtime does not import the Markdown files. Publishing them is a static hosting concern only, so the simulation bundle remains independent of the documentation atlas.

## Verification

A deployment is considered complete only when both checks pass:

1. `freebuff-deploy status` reports `state: active` with no unresolved build errors.
2. `https://vepa.freebuff.app/docs/systems/README.md` returns the atlas content with a Markdown content type instead of the application shell.
